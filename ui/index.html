Detailed Pipeline Architecture Comparison

How Baseline Dense RAG and CARO RAG process multi-hop questions through distinct stages.

Module 2 Architecture

Baseline Dense RAG

A traditional, unconstrained top-k dense retrieval pipeline.

  • 1
    User Query Input: Query is passed directly to the dense embedder without routing or complexity analysis.
  • 2
    Dense Vector Embedding: BAAI/bge-m3 encodes the full query string into a 1024-dimensional dense representation.
  • 3
    FAISS Flat Index Search: Retrieves Top-5 nearest neighbors from 250k document vectors in a single pass.
  • 4
    Direct Prompt Generation: All 5 passages are placed in the prompt and passed to Gemma-3:4B with no verification.
  • 5
    Unconditional Output: Always forces an answer, resulting in hallucinated names or entities when multi-hop links are missing.
CARO RAG Architecture

CARO Context-Aware Orchestration

A multi-stage adaptive orchestration pipeline with evidence gating.

  • 1
    Adaptive Query Router (Module 3): Classifies whether the query requires retrieval or can be answered directly, identifying multi-hop dependencies.
  • 2
    Query Expansion & Decomposition: Decomposes complex questions into intermediate bridge queries and sub-queries.
  • 3
    Hybrid Dense + Sparse Fusion: Executes 8 parallel retrieval passes across FAISS dense vectors and BM25 postings, fused with Reciprocal Rank Fusion (RRF k=60).
  • 4
    Evidence Sufficiency Judge (Module 7): Checks if retrieved passages provide complete, partial, or insufficient facts before generating.
  • 5
    Grounded Synthesis / Safe Abstention: Emits citation anchors ([1], [2]), includes disclaimers on partial evidence, or safely abstains to eliminate hallucinations.
